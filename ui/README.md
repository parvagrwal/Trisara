# Trisara site (`ui/`)

A single static page: what Trisara is, the protocol working from live data, how it works, and the `cast` commands to verify it yourself.

Next.js (App Router, `output: "export"`), TypeScript strict, Tailwind CSS v4. Fonts are self-hosted from `@fontsource-variable`. No analytics, no third-party runtime requests except the indexer and the Signal API.

## Build

```bash
npm install
npm run build      # next build, then scripts/postbuild.mjs; output in ui/out
npm run check      # typecheck, lint, build, then scripts/check.mjs
npm run dev        # local dev server
```

Serve `out/` with any static host, for example `npx serve out`.

`prebuild` and `predev` run `scripts/sync-deployments.mjs --if-present`. It regenerates `src/data/deployments.generated.json` from `../deployments/*.json` and skips quietly when the parent directory isn't there. The generated file is committed, so a build never depends on the parent directory. The script fails if the AnchorClock or Rulebook that the indexer and Signal API poll stops matching the files. It warns when `DEPLOYED.md` lags the JSON files.

## Environment

All optional. See `.env.example`.

| variable | default | use |
|---|---|---|
| `NEXT_PUBLIC_INDEXER_URL` | `https://trisara-indexer.onrender.com` | `GET /state` |
| `NEXT_PUBLIC_SIGNAL_URL` | `https://trisara-signal-api.onrender.com` | `GET /signal` |
| `NEXT_PUBLIC_REPO_URL` | `https://github.com/parvagrwal/Trisara` | source links (branch `main`) |
| `NEXT_PUBLIC_BASE_PATH` | empty | serve from a sub-path, e.g. `/trisara` |
| `NEXT_PUBLIC_WAITLIST_ENDPOINT` | unset | POST `{"email": "..."}` as JSON. Unset means no form is rendered, and the build prints a warning |
| `NEXT_PUBLIC_SITE_URL` | unset | `metadataBase` |

## Data

- **Indexer** `GET /state`, polled every 30 s while the tab is visible. The page understands `schemaVersion: 2` only. `blockTimestamp` is optional: the deployed poller may not send it yet.
- **Signal API** `GET /signal`. Both shapes are accepted: legacy, keyed by symbol (treated as Robinhood Chain 46630), and multi-chain, keyed by `"chainId/SYM"`.
- Requests are plain `fetch(url, { cache: "no-store" })`. There is no query string, because both servers route exact paths, and there are no custom headers, because the indexer does not answer CORS preflights.
- **Replays**: `public/replays/*.json`, generated by `forge test` (Foundry writes into `./ui`). They are rendered per `scenario`; an unknown scenario shows its `incident` and the raw JSON.
- `public/state-latest.json` is a stale committed snapshot. The page never reads it, and `postbuild` deletes the copy in `out/`.

Each source moves through the states loading, waking (pending 4 s or more, for free-host cold starts), warming (indexer 503), ok, stale (last good data kept, plus a "late" or "stalled" chip by snapshot age) and error (no data yet). On failure it backs off 5, 10, 20, 40, then 60 s.

## Checks (`scripts/check.mjs`)

- `out/index.html` and the four `out/replays/*.json` exist; `out/state-latest.json` does not.
- No `Math.random` in `src/` (ESLint also bans it).
- The static HTML of the hero, the session slip and the terminal holds skeletons only: no OPEN/CLOSED, prices, block numbers, latencies or ages.
- `scripts/contrast.mjs`: every text pair in `globals.css` reaches 4.5:1 and every graphic 3:1, including the change flash. Stale data is dimmed by stepping text colours down one level, not with opacity, so it keeps 4.5:1.
